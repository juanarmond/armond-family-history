# Family-assistant Worker

A Cloudflare Worker that answers natural-language questions about the family tree,
grounded only in this repository's data, using Google Gemini (free tier). It is a
stateless RAG proxy: it holds the Gemini API key as a Worker **secret** and the
browser only ever talks to the Worker, never to Google directly.

How it works (per question):

1. Loads the knowledge base from the public site — `knowledge-base.json` (Tier A: a
   summary of every person, every document's title, and the full family/event graph)
   and `name-index.json` — both edge-cached for an hour.
2. Resolves the people and documents the question mentions to IDs (explicit `P-####`
   / `PAR-####` etc., then exact indexed names, then single-word name tokens).
3. For a two-person **"how are X and Y related?"** question, computes the exact
   relationship path by BFS over the family graph, so the model narrates a *verified*
   path instead of guessing one. Living people are never traversable.
4. Fetches the full Tier B records (per-person profiles and per-document
   transcriptions) for just the resolved entities.
5. Asks Gemini **2.5 Flash** (falling back to **2.0 Flash-Lite** if the daily quota
   is hit) and streams the answer back as plain text.

The knowledge base is generated by `scripts/build_knowledge_base.py` with the same
living-person privacy filter as the public site, so nothing private is reachable.

The Worker source is [`worker.js`](worker.js). It is **not** part of the GitHub Pages
build — it runs on Cloudflare and the site calls it over `fetch`.

## Prerequisite: a free Gemini API key

1. Go to <https://aistudio.google.com/app/apikey> and create a key (no card needed).
2. Keep it secret — it is set on the Worker below, never in the site or git.

> Verify the free-tier model IDs and limits at
> <https://ai.google.dev/gemini-api/docs/rate-limits> before deploying — Google
> rotates them. Update `MODELS` in `worker.js` if `gemini-2.5-flash` /
> `gemini-2.0-flash-lite` have changed.

## Deploy (dashboard, ~3 minutes)

1. **dash.cloudflare.com → Compute (Workers) → Create → Create Worker.** Name it
   `family-assistant`. Deploy the default, then **Edit code**.
2. Paste the whole contents of `worker.js` over the template, and **Deploy**.
3. **Settings → Variables and Secrets → Add → Secret.** Name it exactly
   `GEMINI_API_KEY`, paste your key, and save.
4. Copy the Worker URL — it looks like
   `https://family-assistant.<your-subdomain>.workers.dev`. Send it to the
   maintainer; it goes into `ASSISTANT_API` in `family-tree-viewer/app.js` and the
   chat widget goes live.

Until `ASSISTANT_API` is set, the chat widget stays hidden — nothing breaks.

## Deploy (Wrangler CLI, alternative)

```sh
npm i -g wrangler
wrangler login
cd workers/family-assistant
wrangler secret put GEMINI_API_KEY     # paste the key when prompted
wrangler deploy
```

## Full local test (before pushing anything)

You can exercise the whole feature — viewer widget + Worker + Gemini — entirely on
your machine, reading a **local** copy of the knowledge base so nothing needs to be
pushed first.

1. **Build the knowledge base locally** (from the repo root):

   ```sh
   make knowledge-base            # writes family-tree-viewer/kb/
   ```

2. **Serve the repo** (from the repo root) so the viewer *and* kb/ are on localhost:

   ```sh
   python3 -m http.server 8765
   ```

   Viewer → <http://127.0.0.1:8765/family-tree-viewer/> ·
   kb/ → `http://127.0.0.1:8765/family-tree-viewer/kb/`

3. **Configure and run the Worker** (in another terminal):

   ```sh
   cd workers/family-assistant
   cp .dev.vars.example .dev.vars        # then edit: real GEMINI_API_KEY, keep the local KB_BASE
   npx wrangler dev                      # serves the Worker at http://localhost:8787
   ```

   `.dev.vars` (gitignored) supplies `GEMINI_API_KEY` and `KB_BASE` — the latter
   points the Worker at the locally-served kb/, so you test current data without a deploy.

   Smoke-test it directly:

   ```sh
   curl -N http://localhost:8787 -H 'Content-Type: application/json' \
     -d '{"question":"How is Frédéric Rutschmann related to Iris?","lang":"en"}'
   ```

4. **Point the viewer at the local Worker** — open the viewer (step 2), open the
   browser console, and run:

   ```js
   localStorage.setItem("armond-assistant-api", "http://localhost:8787")
   ```

   Reload. The **Ask** pill now appears; the chat talks to your local Worker. (Clear
   it with `localStorage.removeItem("armond-assistant-api")`.)

Once it all works locally, deploy the Worker (above), set `CONFIGURED_ASSISTANT_API`
in `family-tree-viewer/app.js` to the deployed URL, and push.
